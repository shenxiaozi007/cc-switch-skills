# 生成前端接口对接文档

## 输入与输出

- 输入优先从当前仓库的 Git diff、路由、控制器、业务校验和返回字段中获取；也可使用用户提供的接口清单。
- 输出为当前项目 `docs/` 目录下的 Markdown 文件。
- 文档只保留标题、统一接口前缀说明和接口汇总表。除非用户明确要求，不增加字段详解、请求示例、响应示例或额外章节。

## 工作流程

1. 检查当前工作区和 Git diff，确定本次业务范围。
2. 根据项目路由配置确认每个接口的 Method、完整前缀和相对地址。
3. 根据控制器、业务层校验和模型返回值，确认前端需要新增、修改或删除的参数和字段。
4. 将变更归类为“新增”“修改”或“删除”，一个接口一行。
5. 按下方固定格式生成或更新 Markdown。
6. 运行格式检查，确认表格列数一致、路径和字段名与代码一致。

## 核对规则

- 优先信任实际代码，不根据注释或需求描述猜测已实现行为。
- 路由文件用于确认 Method 和地址；校验规则用于确认必填、类型、范围和枚举；返回字段以实际查询列、追加属性和资源转换为准。
- 只写前端需要采取的动作，不展开后端内部实现。
- 对代码中不一致的契约，在表格的“本次前端需要调整”中用一句话明确当前限制，不替后端做未实现的承诺。
- 保留用户已有文档的无关内容；当用户要求“只保留汇总”时，才删除其他章节。

## 输出模板

```markdown
# [业务主题]接口汇总

统一接口前缀：`/[prefix]`。[认证要求]。

| 模块 | 变更类型 | Method | 接口地址 | 本次前端需要调整 |
|---|---|---:|---|---|
| [模块] | [新增/修改/删除] | [GET/POST/PUT/PATCH/DELETE] | `/relative/path` | [前端需要完成的具体调整] |
```

## 文件命名

- 用户指定路径或文件名时优先使用。
- 未指定时，使用 `docs/[业务主题]-前端对接.md`。
- 项目没有 `docs/` 目录时创建该目录。

## 完成标准

- 所有行都能在当前代码或用户提供的契约中找到依据。
- 同一组接口的前缀表达一致，表格内默认使用相对地址。
- 表格中的字段名、枚举值和权限标识使用代码原值并用反引号包裹。
- Markdown 无空白占位、占位标记或未核实描述。
