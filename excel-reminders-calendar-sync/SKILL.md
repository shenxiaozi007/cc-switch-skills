# Excel Reminders Calendar Sync

## Overview

将项目总表类 Excel 文件同步到 macOS 原生应用：

- 读取 workbook 中的项目行、状态列和日期列。
- 将进度为“待开发”的项目写入提醒事项.app。
- 将“完成规划时间”“开发完成时间”“计划上线时间”写入日历.app。
- 同步前后做重复检查，避免反复运行产生重复提醒或日程。

## When To Use

当用户给出 `.xlsx` 项目表，并要求：

- “表格上待开发的加到提醒事项”
- “完成规划时间、开发完成时间、计划上线时间同步到日历”
- “以后按这个流程整理成提醒/日历”
- “项目总表同步到提醒事项和日历”

如果用户只是要编辑表格内容，不使用此 skill。

## Input Contract

默认输入是一份 Excel 项目总表，通常包含这些列：

- `序号`
- `系统`
- `一级分类`
- `二级分类`
- `三级分类`
- `功能点`
- `进度`
- `需求部门`
- `完成规划时间`
- `开发完成时间`
- `计划上线时间`
- `备注`

列名可以不完全一致，但必须先根据表头推断清楚对应关系。遇到合并单元格导出的空白分类时，按上方最近非空值向下补齐分类上下文。

## Output Contract

提醒事项：

- 默认列表名：`开发项`
- 筛选条件：`进度 == 待开发`
- 标题格式：`[序号] 待开发 - 需求部门 / 一级分类 / 二级分类 / 三级分类 / 功能点`
- 备注保留来源文件、工作表、序号、进度、分类和功能点。
- 已有同名提醒时跳过，不重复创建。

日历：

- 默认日历名：`开发项`
- 日期字段映射：
  - `完成规划时间` -> `完成规划`
  - `开发完成时间` -> `开发完成`
  - `计划上线时间` -> `计划上线`
- 标题格式：`[序号] 阶段名 - 需求部门 / 一级分类 / 二级分类 / 三级分类 / 功能点`
- 备注保留来源文件、工作表、序号、字段名、进度、分类和功能点。
- 已有同名日程时更新日期和备注，不重复创建。
- 全天事件必须显示为单日，不得多占一天。

## Workflow

1. 解析 Excel。
   - 使用可用的 Python Excel 库读取 workbook。
   - 打印工作表名、表头、行数、列数，确认实际结构。
   - 只读取用户指定文件，不臆测其他来源。

2. 标准化行数据。
   - 根据表头建立字典。
   - 对 `系统`、`一级分类`、`二级分类`、`三级分类` 这类层级列做向下补齐。
   - 保留原始序号和功能点，避免相同功能点在不同分类下混淆。

3. 同步提醒事项。
   - 找到或创建提醒事项列表 `开发项`。
   - 筛选进度为 `待开发` 的行。
   - 创建前按完整标题检查是否已存在。
   - 输出新增数和跳过数。

4. 同步日历。
   - 找到或创建日历 `开发项`。
   - 对每行的三个日期字段分别创建或更新日程。
   - 空日期不创建事件。
   - 创建前按完整标题检查是否已存在。
   - 输出新增数和更新数。

5. 验证。
   - 提醒事项：反查目标列表中匹配标题的数量。
   - 日历：反查目标日历中匹配序号或来源标识的事件数量。
   - 若用户反馈日历多一天，立即按单日规则修正。

## Calendar All-Day Rule

macOS Calendar 的全天事件容易因为结束日期边界显示成多一天。写入时必须让事件在界面上只显示当天。

推荐规则：

- `start date` 设为当天 `00:00:00`。
- `end date` 设为当天 `23:59:59`，或创建后验证 Calendar 归一化后的结束时间仍在同一天。
- `allday event` 设为 `true`。
- 不要把 `end date` 设为次日 `00:00:00`，除非已确认目标 Calendar 显示不会跨天。

更多实现细节见 [workflow.md](references/workflow.md)。

## User Communication

同步前先告知用户将写入哪个 Reminders 列表和 Calendar 日历。同步后简洁汇报：

- 从 Excel 中识别到多少条待开发提醒。
- 新增/跳过多少条提醒。
- 识别到多少个日期日程。
- 新增/更新多少条日程。
- 哪些日期字段为空因此未创建。

如果需要访问 macOS 提醒事项或日历，按当前运行环境请求权限。
